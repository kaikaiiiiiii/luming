# 覆盖与合并的扩展解释

本文展开解释 README「高阶用法 - 后继定义覆盖」背后的模型。
完整规则见 `docs/parse-rule.md`。

## 为什么"后定义覆盖"只在行间生效

路明 是批处理语言：所有行读入后合并、再一次性渲染。因此"覆盖"发生在**声明之间**，
而声明的先后只在不同行之间才有意义——**同一行写下的结构是一次完整表达，内部没有
先后可言**。由此得到两条正交的规则：

1. **同行并行**：同一行内的多次书写互不覆盖，各按书写位置原样呈现。
2. **跨行覆盖**：不同行对同一主体的再描述，按文档序后行覆盖前行。

## 两个对照

同行并行——两栏按写的样子呈现：

```
Row [ Col [ Titles ] + Col [ Body ] ]
```

跨行覆盖——后写的布局整行替换先写的场景：

```
A / B
A + B
```

结果是一个场景 `A + B`。

## 跨行覆盖可以越过行内书面内容

```
Header / Sidebar + Main [ Tabs / Content ] / Footer
Main [ Good Bad ]
```

第二行是对 Main 内部的再描述，因此 Main 的内部处处都是 Good Bad。
理解要点：第一行的 `Main [ Tabs / Content ]` 不是"Main 的私有定义"，
而是对 Main 内部构造的一次声明；后行的声明按行序覆盖它。
（这一语义与样式系统不同：行内**样式**锚点绑定实例位置、优先于主体级样式，
因为样式是按属性的局部修饰，而内部结构是整值替换。）

## 单行与拆行的等效边界

不存在对同一主体的多次内部声明时，单行长表达式与拆成多行严格等效
（产生相同的声明集合与场景）。存在多次声明时二者可能不同：

```
A[A[A]]          ≡  A[A]
                    A[A]      ← 拆开后变成跨行覆盖，渲染两层
（单行：同行并行，渲染三层）
```
