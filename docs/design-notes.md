## 1. 定位与设计哲学（最终保留）

- **一句话定位**：声明式 UI DSL / 声明式布局语言，编译为组件树（L15181-15190、L11513-11516）。
  不是 HTML 简写，不是设计工具替代品，不负责高保真视觉。
- **起源**：设计图格式对 AI 不友好，工具路线（Figma / Penpot / Inkscape / SVG / HTML 草图）全部放弃
  （L4-13、L804-808），决定做"类似 mermaid/markdown 的简化式设计语言"。
- **核心哲学**（L1314-1348、L4341-4360 等）：
  1. **结构优先**：描述结构树与空间关系，而非视觉样式。
  2. **无二义性**：同一输入永远只有一种解析结果；歧义即报错，不做猜测。
  3. **可逆性**：DSL → 中间结构 → DSL 必须可还原，否则只是 prompt 格式而非语言。
  4. **克制**：不为理论完美把布局 DSL 变成另一门编程语言（L15589）。
  5. **语义与实现分离**：语言层只定义布局语义；是否物化为 DOM 容器由渲染目标决定
     （"Implementation-dependent materialization"，L11128-11134）。
- **明确不做**（v1 Non-Goals，L1233-1239、L8676-8684）：响应式/媒体查询、组件逻辑、
  数据流、选择器、交互、动画、类 CSS 选择器体系。

## 2. 结构语法（最终形态）

### 2.1 运算符与解析顺序

同一行内解析顺序（L15887-15923 定稿）：

1. **`[]` 包含**：`B [ A / C ]` 建立 B 对内部表达式的包含关系（树关系）。
2. **`()` 分组**：建立一个**匿名布局组**，改变内部表达式的结合范围。
3. **`/` 纵向切分**：将当前层级切分为垂直排列的布局单元（外层）。
4. **`+` 横向排列**：在每个垂直组内部，将元素水平排列（组内）。

即 `A / B + C + D / E` ≡ `A / (B + C + D) / E`；
`A + B / (C / D [ E + F ])` 的解析步骤见 L15965-16025。

- `()` 的语义是『布局运算优先级』，**不产生必然存在的 DOM 节点**；Flex 实现可能物化为
  匿名容器，Grid 实现可直接消解（L11045、L16245-16249）。`()` 不可被样式修饰，
  `(A + B): bg red;` 非法（L8495-8500、L6312）。
- `[]` 内部允许**空格省略 `+`**（隐式横向排列）：`A [ B C ]` ≡ `A [ B + C ]`；
  `A[B C[D E]]` ≡ `A [ B + C [ D + E ] ]`（L3874、L16335-16346）。
  空格在 `[]` 之外永远不是结构符号（L3697），顶层必须显式写 `+`。
- 早期『`/` 优先于 `+`』『默认左结合、无优先级差异』两个方案均被否决
  （四宫格 `A + B / C + D` 压测失败，L4304-4377）；最终采用上述布局组模型。
- 换行不承载结构语义；多行等效性来自关系合并（见 §4），不是行序布局。

### 2.2 两种结构关系（写进 v1 语义文档的基本原则）

> **Luming 的结构关系只有两种：Containment（包含，树关系）与 Layout Order（有序布局组，
> 同级排列）。前者构成层级树，后者构成同级有序布局。**（L15879-15883）

- `A + B + C` 声明"A、B、C 属于同一个水平布局组，顺序 A → B → C"，不是两两关系。
- `A [B / C]` 同时声明包含（A 含 B、C）与 B/C 的垂直布局组。
- 语义上是布局组；实现上可以用链式记录，但那是编译细节，不是 IR 结构（L15832-15836、L16253-16283）。

### 2.3 样式语法

- `Name: token; token; ...`：`:` 开始，`;` 分隔，最后一个 `;` 行尾可省略（L7121-7130）。
- **属性区禁止结构运算符**：`+ / () []` 不得出现在样式值中（L8590-8599）。
- **`:` 只绑定最近的可修饰 Identifier**（L8552-8566、L6800-6805）；绑定到布局组（如
  `Item + (Item + Item): bg red`）直接报错（L6887）。
- 样式 token：预设缩写（`bg`、`rd` 等）、预设类（`tab`/`card`/`label`）、裸数字/百分比（宽度）、
  完整 CSS 属性对。`*` 重复语法糖不进 v1（L7132-7134）。
- 五类报错条件见 L8603-8612。

## 3. 主体、实例与样式作用域

- **主体（Entity / 模板）**：由名称标识的结构定义单元，含默认样式集合与默认子结构列表；
  主体本身不直接渲染。**模板注册与实例生成是两个完全不同的阶段**（L14383-14388）。
- **实例（副本）**：关系表达式中出现的主体在每个位置生成一个实例。
  `List [Item Item Item]` = 同一主体的三个实例（L6549-6554）。
- **样式作用域三层**（L6609-6649）：
  1. **类型级**：`Item: bg red;` 作用于该主体的全部实例。
  2. **位置级（行内）**：`List [Item: bg #99f; Item Item]` 中 `:` 绑定最近 Identifier，
     只作用于该位置的那一个实例。
  3. 优先级原则：**模板提供默认值，显式实例定义优先级更高**（L15459）——
     行内 `#99f` 与类型级 `Item: bg #f99;` 各自生效，第一个实例 `#99f`，其余 `#f99`。
- 实例不可命名、不可被引用；行内样式是实例粒度的最大宽容（L12889）。
  不支持 nth-child / 选择器（L6893-6945）。

## 4. 多行声明与覆盖语义（约束集模型）

最终模型（L15621-15752、L16564-16586）：

- **一行结构表达式 = 一组布局约束的声明**，对该行中**所有**主体都建立关系，
  不是只对行首主体。
- **包含关系中的父是唯一的，父→子列表是覆盖式的**：同一父主体的子关系声明，
  后声明覆盖冲突部分。`Main[Tabs / Content]` 后跟 `Main[Good Bad]` → `Main[Good Bad]`。
- **子→父的映射不是唯一的**：每一个映射都会生成子的实例。
  `Page [ Content ]` + `Main [ Content ]` = Content 两个实例（L12693）。
- 行内重复同名（`List [Item Item Item]`）= 多实例，不是覆盖。
- 无任何关系的单行 `Name`：若该主体已存在且有归属，此行不提供新信息、不单独渲染；
  只有"无父主体"（从未被任何 `[]` 包含）才按首次出现顺序独立成景（L12877-12885）。
- 需要保留的仅是**声明来源/优先级信息**（如行内样式属于哪个实例位置），
  属于语义数据，不是为保存 AST（L16564-16582）。

## 5. 展开与循环（正式语义）

《Luming v1 递归展开规则》正式草案（L14036-14199）：

- **术语**：
  - **模板**：名称首次声明产生的结构定义单元（默认样式集合 + 默认子结构列表），不直接渲染。
  - **显式子节点**：源码中通过嵌套语法直接写出的子结构。
  - **模板子节点**：展开阶段经模板默认子列表生成的子节点。
- **展开模型**：两阶段——①构建阶段：建模板表、记录覆盖式父→子关系、累积样式，不生成实例；
  ②展开阶段：从所有"无父模板"递归展开生成实例树（L14084-14095）。
- **循环控制（固定点/路径栈方案）**（L14099-14124，三选一后采纳方案三，L13410）：
  - 展开时维护路径栈 `path = [T1..Tn]`；
  - 子节点 C 为**显式**子节点 → 永远允许展开（显式结构永远优先、完整保留，L14128-14168）；
  - C 为**模板**子节点且其模板名已在路径栈中 → 生成实例但不再展开其子节点（**终止节点/Terminus**）；
  - 否则正常展开。
- **终止节点**：仍正常渲染、样式生效，仅不再展开，无特殊视觉标记（L14172-14180）。
- 性质：确定性、有限性、显式优先、模板安全、不依赖最大深度、无运行时状态（L14184-14193）。
- 循环引用不是错误；"模板图必须是 DAG"与"限制最大深度"两个方案均被否决（L13165、L13098、L13252）。
- **注**：上表"显式子节点 → 永远允许展开"的字面条款已被 §9.1 的裁决修正——终止节点是
  命中路径的裸子节点本身，而非额外生成的副本；检查范围为当前祖先链。最终条款以 §9.1 结案为准。

## 6. 编译架构（最终形态）

- **Parser 不需要保留完整 AST**（L16376-16588）：源码不是 AST 的序列化，
  而是对布局关系模型的声明。Parser 的职责是**把 DSL 声明转换成规范化的
  Entity / Relation / Style 记录**（关系表/关系图），渲染阶段再重建布局结构。
- 同一行长表达式与拆成多行的写法产生**完全相同的关系记录**，因此天然等效（L16465-16508）。
- **三层编译**（L14410-14505）：
  1. Parser：语法 → 结构记录（递归下降，手写 tokenizer，不关心任何目标框架）；
  2. Semantic Builder：模板注册、父子关系构建、样式合并、循环控制 → TemplateRegistry + InstanceTree；
  3. Target Generator：`generateHTML(tree) / generateVue(tree) / generateReact(tree)`，
     插件 = 函数表，不做 Webpack 式插件系统。
- **流水线**：Source → Parser → Entity/Relation/Style 记录 → Resolve → 布局树 → Renderer（L16352-16364）。
- **逐行读入 + 一次性渲染**：先全部读入、合并、再一次性展开；不存在"行渲染时实时修改先前副本"
  （L13157-13198、L16564）。纯静态，无运行时。
- **渲染器策略**：布局组语义优先映射 **CSS Grid**（可消解 `()` 与跨层级布局，无多余容器），
  Flex 作为需要匿名容器的对照实现（L10869-11044、L11244）。
- AST/IR 分层：AST 答"源码写了什么"，Layout IR 答"页面结构是什么样"
  （L16084-16210）；工程上可简化为直接产出关系记录（L16388-16586）。

## 9. 遗留开放问题（讨论存档未定案，需用户仲裁）

0. **核心矛盾：容器断言的身份——模板级覆盖还是位置级呈现**（已定性，方向已裁决为 P）：

   三条既有规则在嵌套同名/同行同名容器上不可兼得：
   ①展开前检查（截断递归）；②拆分等效（长行 ≡ 拆成多行）；③后定义覆盖。
   由 ②+③：`A[A[A]]` 被拆成两条 `A[A]` 再覆盖为一条，渲染两层，书面结构丢失。
   若加"模板的完整呈现"（位置级保留书面结构），则 `A[B]+A[C]` 下：
   位置级 → `A[B]+A[C]`；模板级 → `A[C]+A[C]`；合并 → 未定义（存档已搁置）。

   **锐利形式**：规则②（无条件拆分等效）+ 规则③（无条件后覆盖）⇒ 书面结构必然不保留；
   要保留书面结构，必须弱化②或③之一。

   **根因（用户补充定性）**：冲突归属于第四条隐性规则——Luming 是"全部读入后统一渲染"的
   批处理模型，不是逐行执行的程序语句。逐行执行下 `A[B]+A[C]` 后写 `A[D]` 本无冲突：
   已渲染位置不被追溯，`A[D]` 只影响未来实例——该思想实验的可见结果恰与 P 一致，
   是 P 的最强论据。但批处理模型不可放弃：前向引用（quickstart 第 1 行使用 Content、
   第 2 行才定义；`A[B]`+`B[A]` 中 B 先被使用后被填充）、"无运行时"定案（L12748-12813、
   L14193）、单行 ≡ 拆行等效，全都依赖它。因此冲突只能在批处理内静态解决：
   **P = 批处理模型内的"书写时刻捕获"**——位置断言天然携带自己的书写时刻（不可追溯修改），
   可覆盖域（模板默认池 / 顶层关系 / 样式）按文档序后者胜。批处理 ≠ 顺序无关：
   早期设计的"顺序无关"（L3121-3189）早已被规则③隐式否定，P 使之分域显式化。

   **用户裁决（倾向 P）**：语言为人的视觉服务，代码呈现应与视觉呈现一致；
   拆分逻辑当初只为 parse 易实现，考虑改动或取消。三条残余规则：
   ①递归截断；②模板原样呈现；③后覆盖不报错。

   **条款定稿（选项二：行内并行 + 行间覆盖，2026-09-19 用户拍板）**：
   用户四点取舍：①递归截断保留；②后覆盖保留；③拆分规则废弃（一切矛盾的源头）；
   ④"实例级/主体级"双层模型否决（独立断言行可能不渲染，违反所见即所得；需额外标志）。
   在 A[A[A]] 收敛为两层、Row[Col[Titles]+Col[Body]] 两栏同质等后果被明示后，
   用户改选**选项二**：同一行内的声明互不分先后、按书写位置原样呈现；
   跨行对同一主体的再描述按行序后者胜（可覆盖行内书面内容）。
   详细条款见 `docs/parse-rule.md`（权威文档）；design-notes 保留裁决轨迹：
   v1（位置不可覆盖）→ v2（行边界）→ v3（双层断言，被否决）→ v4（纯级联，被选项二取代）
   → **定稿 = 选项二**。

   定稿要点：
   - **同行并行**：同一行内对同一主体的多次内部声明互不覆盖，各绑定其书写位置
     （`A[A[A]]` 三层、`Row [ Col[Titles] + Col[Body] ]` 两栏各异、
     `List [Item[Icon] Item Item]` 仅第一项含 Icon）。
   - **行间覆盖**：跨行重声明按行序后者胜，可覆盖早先行内的书面内容
     （`A[B]` 行 + `A[C]` 行 → `A[C]`；quickstart + `Main[Good Bad]` → Good Bad 胜）。
   - **场景选择**：文档序首次放置成景；顶层主体全部已放置的多主体关系行替换既有场景
     （整行替换）；已放置主体的单主体行仅作声明。
   - **递归截断**：裸引用取定义展开前检查祖先链，命中即自身为终止节点；
     行内书面位置原样渲染、不检查。
   - **主体级定义池**：裸位置回退时，只取**早于场景行**的声明（同行声明不入池）。
   - 样式系统不变：主体级按属性级联，行内锚点绑定最近 Identifier 且优先于主体级。
   - 诊断：同一主体内部构造被多次声明 → warning。
   - 未决边缘：部分重叠的关系行（`A / B` 后跟 `C / A`）当前按新场景处理。
